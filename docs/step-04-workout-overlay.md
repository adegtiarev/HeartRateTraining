# Step 4 — Ride with the heart rate overlay

**Outcome.** During a recording or paused workout, the rider can tap **Show overlay**, switch to a navigator and read their pulse against the current zone color from that ride's snapshot. One finger moves the window. A two-finger pinch resizes the window and its digits. The app remembers both adjustments for future workouts. **Hide overlay** closes the window and the ride continues. **Finish** removes it before Results opens. [Milestone 4](../IMPLEMENTATION_PLAN.md#4-ride-with-the-overlay)

## 1. Share the workout's live reading

`HeartRateApplication` already owns the sensor repository and recorder. Collect `SensorRepository.state` for its latest sample and `WorkoutRecorder.state` for the ride ID, phase and zone snapshot. Extract the reading and zone calculation from `WorkoutScreen` into a plain Kotlin function shared by the screen and overlay. Classify with `ride.zones?.zoneFor(bpm)`. The service can collect these flows while Maps is in front, independently of the screen's 250 ms timer. [Workout screen](../app/src/main/java/arg/adegtiarev/heartratetraining/ui/WorkoutScreens.kt) · [Workout ViewModel](../app/src/main/java/arg/adegtiarev/heartratetraining/ui/WorkoutViewModels.kt) · [Sensor repository](../app/src/main/java/arg/adegtiarev/heartratetraining/sensor/SensorRepository.kt)

| Reading while the overlay is enabled | Visible window | TalkBack description |
| --- | --- | --- |
| Fresh BPM with configured zones | BPM digits, with the saved zone color filling the entire window | Localized pulse with its unit and zone number |
| Fresh BPM on a ride started with unconfigured zones | BPM digits on a neutral black background | Localized pulse with its unit |
| Waiting for the strap, contact lost, disconnected or expired | White dash on black | Localized missing-reading description |

Use the repository's five-second freshness rule. Each valid reading restarts the timeout, including a repeat of the same BPM. A disconnect or reported contact loss clears the reading immediately. Before drawing on Show or after the display wakes, have the repository recheck the sample's age against its monotonic clock. During Pause the overlay follows fresh readings while active time and the stored sample count stay fixed.

Below 10% strap battery, the overlay alternates its normal background with white every 250 ms throughout recording and Pause. For a pure white zone the alternate color is black. Each phase uses contrasting digits. TalkBack includes a steady low-battery warning alongside the reading. Reaching 10%, losing the connection or hiding the window stops the flashing.

## 2. Enable the overlay from Workout

Start each ride with the overlay hidden. Keep the rider's choice in memory for that ride ID. Android stores the separate permission to draw over other apps. Add **Show overlay** and **Hide overlay** to the recording and paused states of Workout. The notification and Home's return action already provide routes back to these controls. [Workout navigation](../app/src/main/java/arg/adegtiarev/heartratetraining/ui/HeartRateScreens.kt)

1. Declare `SYSTEM_ALERT_WINDOW` in the manifest. On **Show overlay**, check `Settings.canDrawOverlays(context)`. When access is already granted, show the window immediately.
2. When access is missing, explain why the app needs it and offer **Open settings** or **Cancel**. Launch `ACTION_MANAGE_OVERLAY_PERMISSION` from the visible activity. On API 29 use the app's entry when the system provides it and fall back to the list. On API 30+ guide the rider to select the app by its localized name in the system list. [Special access workflow](https://developer.android.com/training/permissions/requesting-special) · [Overlay settings intent](https://developer.android.com/reference/android/provider/Settings#ACTION_MANAGE_OVERLAY_PERMISSION)
3. Keep the pending ride ID across activity recreation. On return, recheck access in `onResume()` and complete the request once, only for the same recording or paused ride. On cancellation, denial or an unavailable Settings screen, clear the request and leave **Show overlay** available. A retry starts with another rider tap. Keep the launcher and permission checks at the Android boundary. Have `WorkoutViewModel` expose the overlay status as immutable UI state. [Activity](../app/src/main/java/arg/adegtiarev/heartratetraining/MainActivity.kt)

## 3. Give the existing workout service one window

Pass Show and Hide actions with the ride ID through shared in-process state to the running `WorkoutService`. Keep service startup tied to **Start workout**. This `connectedDevice` foreground service owns the view and its collectors. The UI reflects successful attachment and can report a window error independently of recording status or notification permission. [Workout service](../app/src/main/java/arg/adegtiarev/heartratetraining/workout/WorkoutService.kt) · [Recorder lifecycle](../app/src/main/java/arg/adegtiarev/heartratetraining/workout/WorkoutRecorder.kt)

- Use a single `TextView` in a `TYPE_APPLICATION_OVERLAY` window. On API 30+ obtain its `WindowManager` and view resources from a display-associated window context of that type. On API 29 use the service's window manager. Start in the upper-right corner. Fit the window to the reading, keep it inside the usable area and remeasure on rotation or font changes. `FLAG_NOT_FOCUSABLE` lets the navigator keep input focus and receive gestures outside the window. [Window context](https://developer.android.com/reference/android/content/Context#createWindowContext(int,%20android.os.Bundle)) · [Window flags](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_NOT_FOCUSABLE)
- Add, update and remove the view on the main thread. Update the attached view only when its displayed content changes. Reuse the workout's contrast calculation and existing number, plural, zone and missing-reading resources. Give the window one readable TalkBack description. Let the rider inspect it on demand without announcing every heartbeat. Provide English, Russian and Spanish text for the controls, rationale and errors. [Pulse display and contrast](../app/src/main/java/arg/adegtiarev/heartratetraining/ui/HomeScreen.kt)
- Recheck access just before attachment. While attached, observe this app's `OPSTR_SYSTEM_ALERT_WINDOW` with `AppOpsManager.startWatchingMode()` and recheck on a change, including while the activity is stopped. On revocation or a window-manager failure, clear the request, release the view and offer a retry from Workout. A foreground app can temporarily suppress overlays on its own windows. Keep the rider's choice through that suppression so the pulse returns on Maps. [App-op change listener](https://developer.android.com/reference/android/app/AppOpsManager#startWatchingMode(java.lang.String,%20java.lang.String,%20android.app.AppOpsManager.OnOpChangedListener)) · [Android overlay visibility](https://developer.android.com/reference/android/view/Window#setHideOverlayWindows(boolean))
- Make Show and Hide safe to repeat. Hide detaches the view, cancels the reading collector and unregisters the app-op listener. Use the same cleanup in `WorkoutService.end()` before stopping the service and in `onDestroy()`, including after a recording error. Clear the ride's request so a late permission result cannot reopen it. A fresh process opens the recovered draft for Save or Discard with the overlay off.

## 4. Move and resize the window

Drag with one finger anywhere on the window. Start a pinch with both fingertips on the window to scale the background and digits together. The first-use scale is 2.0 on the existing 0.75–3.0 scale, equivalent to doubling the original 30 sp digits. A previously saved scale takes precedence. The midpoint stays under the fingers as far as the screen edges allow. A minimum 48 dp touch target keeps the smaller window usable. The digits also respect Android's font size setting. The app reserves room for three digits to keep the badge steady as the pulse changes.

During a drag, update the window directly from the touch position. On API 34 and later, disable Android's window movement animation so the window tracks the finger. At the end of the gesture, save the scale and both position fractions together in the app's private preferences. Each fraction describes how far the window has moved between the available edges. Recalculate those edges using the current window size and usable screen bounds when the phone rotates. The next **Show overlay** restores that geometry, including on a new ride or after process death. [Window movement animation](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#setCanPlayMoveAnimation(boolean)) · [Window metrics](https://developer.android.com/reference/android/view/WindowManager#getCurrentWindowMetrics()) · [Multi-pointer motion events](https://developer.android.com/reference/android/view/MotionEvent)

## Verification and acceptance

**Deterministic readings.** Set the zone starts to 108, 126, 144 and 162 BPM. Give zone 3 a black background and zone 4 a white one. Send 125 at 0 ms, 126 at 1,000 ms and 126 again at 2,000 ms. Expect zone 2, then white digits on black for zone 3. At 6,999 ms both displays still report 126. At 7,000 ms the overlay shows a white dash on the same black background and its description reports a missing reading. Send 144 to recover with black digits on white. Also cover 98 BPM in zone 1, 172 BPM in zone 5, an unconfigured ride and a settings edit after Start. The current ride must keep its original thresholds and colors.

**Android checks.** Extend the existing `syntheticWorkout=true` fixture on API 29 and 37. Run the JVM tests, lint, debug and release builds and the connected suite. [Build commands](step-03-record-workout.md#verification-and-acceptance) · [Synthetic runner invocation](step-03-record-workout.md#verification-record)

- Exercise grant, denial, retry, revocation and rotation during the Settings round trip. Deliver a late grant after Finish and verify the window count stays at zero. Simulate a failed attachment and verify recording continues.
- Repeat Show and Hide. Check the window count alternates between one and zero while one sensor connection feeds the same Room draft. Verify that Hide preserves subsequent readings, Pause freezes writes while the digits update, and Finish removes the window and notification. Repeat with notifications denied on API 37.
- Inspect the actual overlay and its accessibility node with another app in front. Check all three locales and large text. Verify that changing from 98 to 126 BPM keeps the window steady. On API 37 visit a window that suppresses overlays, then return to Maps and verify the latest reading reappears.
- Move the window over another app, pinch it in both directions, drag it to an edge and rotate the display. Compare its actual bounds and digit height. Hide and show it, finish and start a new ride, then repeat after restarting the app.

**Pixel 6a, Coospo H9Z and Google Maps.**

1. Wear the strap, choose a recognizable palette with a black zone around the current pulse, start a ride and enable the overlay. Switch between Maps and another app. Drag the window away from a navigation control and pinch it to a comfortable size. Check it on light and dark maps and after rotation. Pan, zoom and tap a map control outside the window. On the next ride, check that the chosen size and position return.
2. Interrupt contact while the digits are on black. Check the dash and TalkBack description, then restore contact and confirm fresh digits return. Lock and unlock the phone with Maps in front. Pause, observe live BPM, resume and hide the overlay. Verify later samples belong to the same ride.
3. Re-enable the overlay and finish from Pause. Check that Results opens with the window gone, save the ride and reopen it from History. On a separate run, decline access, grant it on retry, then revoke it in Android Settings and return to Maps. Verify the window is gone and check capture continuity. If Android stops the process, check the existing draft recovery on relaunch.

The rider used the overlay during a workout with the Pixel 6a and Coospo H9Z and requested larger digits at first use and more space around them.
